# Clone 选择非空目录报错计划

## 总目标和验收标准

总目标：修复 clone 到非空 folder 时报 `destination path '.' already exists and is not an empty directory` 的问题，让用户选择的 folder 表示克隆父目录，实际仓库落到该 folder 下由远端 URL 推导出的子目录。

验收标准：

- 输入 `https://example.com/repo.git` 并选择 `/target` 时，后端执行等价于 `git -C /target clone https://example.com/repo.git repo`。
- `/target` 内已有其他文件不会导致 clone 到 `.` 的错误。
- 取消 URL 或 folder 选择仍返回取消结果。
- clone 日志与实际执行命令一致。
- 相关单测、lint 通过，或清楚说明与本次无关的已有失败。

## 任务拆分

## 风险点

- URL 目录名推导若过度复杂容易引入边界误判，因此只覆盖常见 Git 远端格式，不尝试解析所有 URL 变体。
- 如果用户原本确实想 clone 到一个已存在的空 folder 本身，行为会从“填充该 folder”变为“在该 folder 内创建子目录”。但这与 `Clone Here` 和选择非空 folder 的用户预期更一致，也避免对已有目录内容产生风险。
- 不自动处理目标子目录已存在的情况，避免覆盖或重命名导致的非预期结果。
