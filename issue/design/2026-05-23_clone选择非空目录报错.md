# Clone 选择非空目录报错设计

## 需求背景

当前 Webview 顶部 Clone 按钮通过 RPC `git.clone` 调用 extension 后端的 `GitService.clone()`。该方法先让用户输入远端仓库地址，再用 `showOpenDialog` 选择文件夹，随后执行：

```ts
simpleGit(targetDirectory).clone(url, ".")
```

这表示把用户选择的文件夹当作仓库根目录本身，并让 Git 将内容克隆到 `.`。当用户选择的文件夹已有其他文件或目录时，Git 会报错：

```text
fatal: destination path '.' already exists and is not an empty directory.
```

从按钮文案 `Clone Here` 和普通 Git/VS Code 使用习惯看，用户选择的 folder 更像“克隆父目录”，期望仓库被克隆到该目录下自动生成的仓库子目录，而不是覆盖或占用这个 folder 本身。

## 需求总结

本次将 Clone 的目标目录语义改为：

- 用户选择的 folder 是克隆位置的父目录。
- 后端根据远端 URL 推导仓库目录名，例如 `https://github.com/owner/repo.git` 克隆到 `<folder>/repo`。
- 非空父目录允许存在；只要求最终仓库目标子目录不能已存在。
- 取消输入 URL 或取消选择 folder 时仍返回 `Clone cancelled`。
- 不改变 Webview RPC 契约，不新增前端字段，不调整 pull/push/fetch/checkout 等其他 Git 操作。

完成后的可观察结果：

- 选择包含其他文件的 `/target` 时，输入 `https://example.com/repo.git` 会执行等价于 `git -C /target clone https://example.com/repo.git repo`。
- 不再因为 `/target` 非空触发 `destination path '.' already exists and is not an empty directory`。

## 详细需求

### 调用链路

- Webview：`packages/webview/src/app/App.tsx` 发起 `git.clone`。
- RPC：`packages/extension/src/backend/rpc/gitHistoryRpcHandlers.ts` 将 `git.clone` 转发到 `GitService.clone()`。
- 后端：`packages/extension/src/backend/git/GitService.ts` 负责输入 URL、选择目录、记录日志、执行 clone。

### 功能规则

1. URL 输入保持在 `GitService.clone()` 顶层处理，空值视为取消。
2. 文件夹选择保持在 `GitService.clone()` 顶层处理，未选择视为取消。
3. 根据远端 URL 推导 clone 目录名：
   - 去掉 URL 末尾的 `/`。
   - 取最后一段路径或 scp-like URL 冒号后的最后一段。
   - 去掉末尾 `.git`。
   - 示例：
     - `https://github.com/owner/repo.git` -> `repo`
     - `git@github.com:owner/repo.git` -> `repo`
     - `ssh://git@example.com/owner/repo.git` -> `repo`
4. 执行 clone 时使用用户选择目录作为工作目录，仓库目录名作为 clone destination：
   - `simpleGit(parentDirectory).clone(url, repositoryDirectoryName)`
5. 日志记录与实际命令保持一致：
   - `git -C <parentDirectory> clone <url> <repositoryDirectoryName>`

### 边界条件

- URL 无法推导目录名时，返回 `Clone cancelled` 或可理解的失败结果。本次优先通过输入校验避免执行不明确 clone。
- 不在 clone 目标子目录已存在时静默覆盖、删除或自动重命名，保持 Git 默认失败行为，避免数据风险。
- 不新增文件系统预检；目标子目录存在与权限问题继续由 Git 返回具体错误。

### 接口、数据和兼容性

- RPC 请求和响应类型不变：`git.clone` 仍无入参，返回 `OperationResultViewModel`。
- 不涉及数据库、配置、migration 或外部服务。
- `GitServiceInput.gitClone` 的测试注入签名需要从“目标目录 + URL”调整为“父目录 + URL + destination”。这是内部测试 seam，不影响扩展对外契约。

### 测试策略

- 更新 `packages/extension/test/unit/gitService.test.ts` 中 clone 相关测试，验证：
  - `https://example.com/repo.git` 选择 `/target` 时调用 `gitClone("/target", url, "repo")`。
  - scp-like URL `git@example.com:owner/repo.git` 能推导为 `repo`。
  - clone 日志从 `git -C /target clone <url> .` 更新为 `git -C /target clone <url> repo`。
- 运行 extension 单测、lint，以及项目级 lint。若全量 lint 因用户现有改动失败，需要说明失败点与本次改动关系。
